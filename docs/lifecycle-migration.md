# Lifecycle Migration Ledger

This ledger tracks the cpkt CMake lifecycle cutover until lonejson fully
converges on the shared lifecycle command and artifact contract.

| Old behavior | New lifecycle surface | Preserved behavior | Verification | Status |
| --- | --- | --- | --- | --- |
| Linux builds could bypass the default Bootlin compiler by setting an explicit host compiler. | All Linux builds use a configure-provisioned pinned Bootlin GCC collection selected by the target toolchain; resolver discovery reports every lifecycle target and optional osxcross status. | Native debug, host release, fuzz, and cross builds still use the same target IDs and dependency bundles. | `lonejson_compiler_selection_tests` asserts compiler, linker, sysroot, libc, and explicit host compiler override handling; `lonejson_cpkt_toolchain_resolver_tests` asserts the inventory and missing-target contract. | Complete |
| Release dependency bundles were installed under `.deps/c.pkt.systems`. | Extracted dependency installs live under `.cache/c.pkt.systems`; immutable, SHA-256-verified SDK archives live in `${CPKT_DEPENDENCY_CACHE:-${XDG_CACHE_HOME:-$HOME/.cache}/c.pkt.systems/deps}`, while compiler collections remain in `${CPKT_TOOLCHAIN_CACHE:-${XDG_CACHE_HOME:-$HOME/.cache}/c.pkt.systems/toolchains}`. | Existing c.pkt.systems bundle fetch and validation behavior is preserved; local extraction can be regenerated offline from the shared archive. | Fetch cache-contract tests cover retries, offline reuse, corrupt entries, and competing consumers; release-matrix, clean, package privacy, and archive verification cover generated state. | Complete |
| Host release presets used short names `linux-gnu-release` and `linux-musl-release`. | Release presets use canonical target IDs: `x86_64-linux-gnu-release` and `x86_64-linux-musl-release`. | Compatibility can remain at the Make/script layer only where already documented. | Preset and release-matrix tests assert canonical names and explicit target metadata. | Complete |
| Darwin osxcross link routes used warning-prone absolute `-fuse-ld=<target-ld>`. | Darwin configure, smoke, and package verification routes use PATH plus absolute `--ld-path=<target-ld>`. | Existing optional Darwin artifact behavior is preserved when osxcross is installed. | `lonejson_darwin_linker_route_tests` and release-matrix structural tests assert the target linker route. | Complete |
| Release-candidate builds had no project-prefixed version override. | `LONEJSON_VERSION_OVERRIDE=X.Y.Z` is honored by `release_version.sh`, CMake configure, and `make print-release-version`. | Untagged git worktrees still resolve to `0.0.0` unless the override is explicit; non-git source archives still require injected `VERSION`. | `lonejson_release_version_override_tests` covers script, CMake, Make, and invalid override rejection. | Complete |
| Package verification and privacy checks had partially separate command surfaces. | `package-verify` is the complete checksum-manifest privacy, relocatability, archive, and loader-metadata gate. | Focused aliases `verify-release-archives` and `verify-release-privacy` remain compatibility entry points. | Release artifact/archive verification tests and negative fixtures. | Complete |
| Lua discovery accepted multiple Lua versions and LuaJIT. | Lua tooling is Lua 5.5 only, with `lua-env`, `lua-rock`, `lua-test`, and release Lua artifact checks. | Existing Lua facade behavior is preserved. | Lua runtime discovery, Make surface, rockspec, source-rock, and release artifact tests. | Complete |
| Compose-backed e2e had project-specific command names only. | Standard `scripts/compose.sh`, `scripts/test-e2e.sh`, `scripts/dev-up.sh`, `scripts/dev-down.sh`, `scripts/dev-reset.sh`, `scripts/dev-ps.sh`, `scripts/dev-logs.sh`, and matching Make targets wrap the deterministic local rig. | Existing curl/OIDC/M2M e2e tests remain available as focused targets. | Make help and e2e wrapper tests. | Complete |
| Build, dependency, cross-test, package, timing, fuzz, Darwin availability, and Lua source-rock orchestration was split across Make recipes and bespoke script names. | Applicable behavior is available through standard lifecycle wrappers, with `cross-build`, `cross-test`, and `package-single-header` added to the root Make surface. | Existing target names and the AFL++ runner remain compatible. | Lifecycle Make-surface, release-pipeline, fuzz-target, and Darwin release-matrix checks. | Complete |
| The release matrix only executed native x86_64 tests and relied on script-local bundle fetches; cross/Darwin preset identity was partly inferred by toolchain files. | `release-matrix` uses standard dependency and matrix entry points, executes each runnable Linux target suite under its configured runner, and every release preset explicitly declares target ID, architecture, OS, and libc. | Host-only LuaRocks/tooling checks remain native-only; the optional Darwin target remains locally osxcross-gated. | Lifecycle preset and release-matrix structural tests. | Complete |
| Benchmark checks were part of the normal `test-all`/`prerelease` path. | `test-all` and `prerelease` are deterministic non-benchmark confidence gates; benchmark enforcement remains explicit through `bench-check`, `bench-gate`, Lua benchmark targets, and `prerelease-hardening`. | Existing benchmark commands, baselines, and retry confirmation behavior are preserved. | Release pipeline and test-all hardening tests assert benchmark gates do not run in `test-all` and do run in `prerelease-hardening`. | Complete |
