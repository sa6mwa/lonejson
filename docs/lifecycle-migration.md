# Lifecycle Migration Ledger

This ledger tracks the cpkt CMake lifecycle cutover until lonejson fully
converges on the shared lifecycle command and artifact contract.

| Old behavior | New lifecycle surface | Preserved behavior | Verification | Status |
| --- | --- | --- | --- | --- |
| Linux builds could bypass the default Bootlin compiler by setting an explicit host compiler. | All Linux builds use a configure-provisioned pinned Bootlin GCC collection selected by the target toolchain; resolver discovery reports every lifecycle target and optional osxcross status. | Native debug, host release, fuzz, and cross builds still use the same target IDs and dependency bundles. | `lonejson_compiler_selection_tests` asserts compiler, linker, sysroot, libc, and explicit host compiler override handling; `lonejson_cpkt_toolchain_resolver_tests` asserts the inventory and missing-target contract. | Complete |
| Release dependency bundles were installed under `.deps/c.pkt.systems`. | Extracted dependency installs live under `.cache/c.pkt.systems`; immutable, SHA-256-verified SDK archives live in `${CPKT_DEPENDENCY_CACHE:-${XDG_CACHE_HOME:-$HOME/.cache}/c.pkt.systems/deps}`, while compiler collections remain in `${CPKT_TOOLCHAIN_CACHE:-${XDG_CACHE_HOME:-$HOME/.cache}/c.pkt.systems/toolchains}`. | Existing c.pkt.systems bundle fetch and validation behavior is preserved; local extraction can be regenerated offline from the shared archive. | Fetch cache-contract tests cover retries, offline reuse, corrupt entries, and competing consumers; release-matrix, clean, package privacy, and archive verification cover generated state. | Complete |
| Host release presets used short names `linux-gnu-release` and `linux-musl-release`. | Release presets use canonical target IDs: `x86_64-linux-gnu-release` and `x86_64-linux-musl-release`. | Compatibility can remain at the Make/script layer only where already documented. | Preset and release-matrix tests assert canonical names and explicit target metadata. | Complete |
| Darwin osxcross link routes used warning-prone absolute `-fuse-ld=<target-ld>`. | Darwin configure, smoke, and package verification routes use PATH plus absolute `--ld-path=<target-ld>`. | Existing optional Darwin artifact behavior is preserved when osxcross is installed. | `lonejson_darwin_linker_route_tests` and release-matrix structural tests assert the target linker route. | Complete |
| Release-candidate builds had no project-prefixed version override. | `LONEJSON_VERSION_OVERRIDE=X.Y.Z` is honored by `release_version.sh`, CMake configure, and `make print-release-version`; environment overrides are one-shot, while explicit CMake cache overrides remain deliberate build-directory state. | Untagged git worktrees still resolve to `0.0.0` unless the override is explicit; non-git source archives still require injected `VERSION`. | `make lifecycle-version-contract` checks script/Make lightweight-tag precedence before clean using only the signing-disabled reserved fixture; ordinary CTest separately proves tag-object rejection, CMake override validation, and clearing environment-only overrides. | Complete |
| Package verification and privacy checks had partially separate command surfaces. | `package-verify` is the complete checksum-manifest privacy, relocatability, archive, and loader-metadata gate. | Focused aliases `verify-release-archives` and `verify-release-privacy` remain compatibility entry points. | Release artifact/archive verification tests and negative fixtures. | Complete |
| Lua discovery accepted multiple Lua versions and LuaJIT. | Lua tooling is Lua 5.5 only, with `lua-env`, `lua-rock`, `lua-test`, and release Lua artifact checks. | Existing Lua facade behavior is preserved. | Lua runtime discovery, Make surface, rockspec, source-rock, and release artifact tests. | Complete |
| Native tests and examples relied on the host dynamic loader or `LD_LIBRARY_PATH`. | Every native Linux CMake executable must record the selected Bootlin ELF interpreter and private transitive `RPATH`; curl examples, Lua tests, and Lua benchmarks run through the embedded target runner. | Host shells and LuaRocks remain packaging tooling; Darwin continues to use its native runtime. | Configure-time target coverage plus runtime metadata tests inspect the interpreter and loaded libc for every local CMake executable, then run them directly. | Complete |
| Release checks treated generic local paths as private but did not name the pinned compiler collection. | Package verification rejects Bootlin cache and stable-collection paths in every shipped library, archive, consumer metadata, ELF interpreter, and `RPATH`/`RUNPATH`. | Local CMake executables retain their selected loader and RPATH for direct test execution. | Artifact and archive negative fixtures inject Bootlin text paths and real ELF interpreter/RPATH metadata, all of which must fail verification. | Complete |
| Compose-backed e2e used Docker/nerdctl and generated state beside static config. | `devenv.yaml.in` and `scripts/devenv.sh` provide rootless Podman Kube through the `dev-*` and `test-e2e` Make targets. All generated state lives under `build/devenv/`; old Compose commands and files are removed. | Curl upload rewind, OIDC/OAuth2/JWKS, M2M/signup, TLS fixtures, configurable host ports, and retained-service debugging remain available. | Renderer/isolation/reset regression tests, the complete real e2e run, per-image host ownership probes, and unprivileged reset. | Complete |
| Build, dependency, cross-test, package, timing, fuzz, Darwin availability, and Lua source-rock orchestration was split across Make recipes and bespoke script names. | Applicable behavior is available through standard lifecycle wrappers, with `cross-build`, `cross-test`, and `package-single-header` added to the root Make surface. | Existing target names and the AFL++ runner remain compatible. | Lifecycle Make-surface, release-pipeline, fuzz-target, and Darwin release-matrix checks. | Complete |
| The release matrix only executed native x86_64 tests and relied on script-local bundle fetches; cross/Darwin preset identity was partly inferred by toolchain files. | `release-matrix` uses standard dependency and matrix entry points, executes each runnable Linux target suite under its configured runner, and every release preset explicitly declares target ID, architecture, OS, and libc. | Host-only LuaRocks/tooling checks remain native-only; the optional Darwin target remains locally osxcross-gated. | Lifecycle preset and release-matrix structural tests. | Complete |
| Benchmark enforcement was outside normal confidence gates. | `test-all`, `prerelease`, and `release` include `bench-check` against frozen host C/Lua baselines, with explicit skips when the host has no baseline. | Existing benchmark commands, baselines, and retry confirmation behavior are preserved. | Release pipeline and test-all hardening tests assert benchmark gate coverage. | Complete |

| Helpers used system temporary directories, source-rock builds used a root build directory, and packaging staged under `dist/`. | Tests, verifiers, Lua builds, and packaging stage under physical repository `build/`; staging rejects source paths, traversal, and symlink escapes. | Artifact names, public headers, and ordinary host ownership remain unchanged. | Workspace negative fixtures, source reconstruction, Lua source-rock installation, and the full binary matrix. | Complete |
| Dynamic exports relied on wildcard visibility, and warning failures were limited to release compilation. | Exact public export lists follow enabled features; six private core helpers and dependency symbols stay hidden. All maintained configurations treat compiler and linker warnings as errors. | Public C ABI 26 and the eight Lua entry/interop exports remain unchanged. | Exact build/extracted symbol checks, private-link and private-export negative fixtures, Debug/Release warning-policy checks, and standard proof. | Complete |
| Linux source-rock checks loaded Bootlin modules through host Lua. | Source-rock validation builds an embedding runner with target Lua 5.5.1 and the selected Bootlin runtime, then loads the installed module against its supplied public C SDK. | Host Lua and LuaRocks continue to provide packaging tools. | Real source-rock installation and module loading; public SDK header and export checks. | Complete |

| Darwin discovery required a major-only osxcross alias and missed complete minor prefixes. | The resolver selects the newest complete installed Darwin 25.x prefix, honors exact pins, and feeds configure and all artifact consumers. | Native Apple builds and prebuilt SDK consumption remain supported; MIG is unused and is not provisioned, as explicitly directed by the engineer. | Prefix-selection, pin, native Apple, real linker-route, and real Darwin SDK/smoke verification. | Complete |
| Verified dependency/toolchain archive reuse depended on filenames. | Digest lookup reuses verified bytes across filenames, URLs, and fresh source roots, under shared cache locks. | Pinned dependency and compiler identities stay unchanged. | HTTP-origin request counting, corrupt/partial fixtures, retries, and resolver cache tests. | Complete |
| Linux artifact verification could choose host binutils; SDK packaging copied build files directly. | Verification requires the complete pinned Bootlin collection; SDK staging uses `cmake --install`, with intermediates confined to `build/`. | Shipped library and metadata layout stay unchanged. | Target discovery rejection fixtures, install-tree consumers, full matrix, and artifact privacy checks. | Complete |

| Memcheck covered only the base C test configuration. | Native CTest Memcheck enables all public facades and includes curl rewind and Lua tests, serially. | Existing core and facade behaviors and ABI 26 are preserved; examples and tests initialize adapter storage, and failure tests free partial output. | Full native Memcheck, Lua allocation-failure tests, and the clean confidence pipeline. | Complete |
| Wrapper working directories, fuzz workspaces, and parallel Make invocation could bypass lifecycle boundaries. | Build dispatch resolves the repository; packaging is incremental; destructive helpers validate physical build workspaces; Make serializes targets. | Ordinary Ninja build parallelism and retained fuzz findings remain supported. | Script dispatch, failure propagation, traversal/symlink rejection, and parallel-invocation serialization fixtures. | Complete |
| Darwin privacy scanning included otool diagnostic filenames; its smoke zip lacked its own license. | Scan Mach-O load-command fields and include the project license in the smoke zip. | Relocatable loader names, strict path rejection, and smoke layout are preserved. | Real positive/negative Mach-O probes, license fixtures, and actual Darwin artifact verification. | Complete |
| SDK dependency manifests omitted optional facade consumer requirements. | Record pinned SDK provenance and external curl/OpenSSL facade requirements; validate structured metadata and the project license. | Core SDK linking remains independent of those libraries; no third-party code is embedded in the SDK. | Malformed provenance fixtures and relocated CMake/pkg-config consumers. | Complete |

The release proof graph gives host release and cross-target testing to the
binary matrix once per configuration. Standalone `test-all` retains broad
confidence coverage; `finalize-slice` uses incremental core/header/ABI and Lua
checks. Clean release and final source reconstruction remain mandatory.
Executable release-graph tests check exact stage counts, order, and failure
propagation without invoking builds, hardening jobs, or cleanup.
